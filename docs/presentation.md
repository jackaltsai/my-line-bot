# AI 虛擬陪伴 LINE Bot

打造有記憶、有個性、會主動關心你的 AI 陪伴角色

---

# 專案是什麼？

- 一個部署在 **LINE** 上的 AI 虛擬男友陪伴機器人
- 使用者透過日常 LINE 聊天，就能獲得情緒支持與陪伴感
- 核心不是「問答工具」，而是**有記憶、有個性、會主動關心人的角色**
- 技術上是 Cloudflare Workers + Hono + D1 + Together AI 打造的全 Serverless 服務

---

# 為什麼做這個？

- 現代人情緒陪伴需求高，但不一定有對象能隨時傾訴
- LINE 是台灣最普及的通訊軟體，使用門檻趨近於零
- 一般聊天機器人「回答問題」，但不「記得你、關心你」
- 目標：做出**有溫度、有記憶、有個性**的陪伴體驗，而非制式客服機器人

---

# 核心體驗設計

1. **引導式初見面（Onboarding）** — 建立安全感與基本認識
2. **四種人設** — 沉、言、夜、嶼，各有說話風格
3. **長期記憶** — 記住你說過的事，適時自然提起
4. **主動關心** — 每日問候、消失偵測召回、關係里程碑
5. **貼圖情緒回應** — 貼圖也能被讀懂、被回應

---

# Onboarding：第一次見面的設計

加入好友後，機器人不是立刻丟出功能選單，而是走一段對話式引導：

1. 隱私承諾：「你跟我說的話，只有我們兩個知道」
2. Q1：最近壓力最大的事是？（工作／感情／家庭／其他）
3. Q2：你喜歡什麼風格的陪伴？（溫柔體貼／幽默逗趣／安靜陪伴／都可以）
4. Q3：我可以怎麼稱呼你？（記錄暱稱）

> 目的：讓使用者在互動的第一分鐘，就感受到「被詢問、被記住」

---

# 四種人設，各有個性

| 人設 | 風格 |
|---|---|
| **沉** | 成熟穩重，冷靜分析、可靠依靠感 |
| **言** | 溫柔傾聽，輕柔耐心、擅長接住情緒 |
| **夜** | 神秘深沉，話少但有份量，帶點曖昧詩意 |
| **嶼** | 陽光暖男，開朗活潑、正能量、會撒嬌 |

- 免費方案固定使用「沉」
- 付費方案可用指令**任意切換四種人設**

---

# 人設背後的「談話原則」

不是單純的 system prompt，而是一套完整的對話設計規則：

- 無條件正向關懷 + 主動傾聽鏡像回應
- 客製化記憶：記得使用者的喜好、習慣、近況
- 情感反映優先：難過時先同理，不 Debug、不講道理
- 建立安全依附：面對吃醋/ 不安全感，用「調侃加寵溺」回應
- 每 3–5 輪自然召回一段過去的記憶，且**不能用機器人語氣**
- 每 7–10 輪穿插一次幽默招牌（自嘲 / 假裝吃醋 / 台灣梗）

---

# 免費方案 vs 付費方案

| | 免費方案 | 付費方案 |
|---|---|---|
| 對話額度 | 每日 10 則 | 1500 則，無使用期限 |
| 人設 | 僅「沉」 | 四種人設任意切換 |
| 長期記憶 | 無 | 有（對話歷史帶入 AI） |
| 主動問候 | 無 | 每日主動關心 |
| 情緒深度 | 基礎安撫 | 深度情緒感知 + 記憶召回 |

- 免費使用滿 **7 天** 會觸發一次情感式付費牆訊息
- 使用雙模型分級：免費用小模型省成本，付費用大模型提升品質

---

# 主動關心機制

- **每日問候**（付費方案）：依人設語氣、是否有昨日對話動態調整內容，週一有特別版
- **消失偵測召回**：24 小時 / 48 小時 / 7 天沒互動，分階段推播不同關心訊息
- **關係里程碑**：第一次對話、累計 50 輪、認識 7 天、認識 30 天，各自觸發專屬訊息
- **貼圖情緒回應**：辨識貼圖情緒類別（開心/愛心/難過/感謝/抱歉），依人設給出對應反應

# 技術架構

```
LINE 使用者
    │  Webhook（訊息 / 貼圖 / 加好友事件）
    ▼
Cloudflare Workers（Hono 框架）
    │
    ├─ 簽章驗證（LINE Channel Secret）
    ├─ 使用者狀態機（Onboarding / 額度 / 人設）
    ├─ Together AI（雙模型：免費小模型／付費大模型）
    ├─ 簡轉繁保險（OpenCC）
    └─ Cloudflare D1（使用者狀態、對話記憶、用量紀錄）

Cron Trigger（每日 09:00 台灣時間）
    → 每日問候 + 消失偵測召回
```

- 全 Serverless：Cloudflare Workers 承載邏輯，D1 作為資料庫
- Webhook 先立即回應 200，再非同步處理，避免 LINE 平台逾時

---

# 資料設計重點

**users**：方案、人設、額度、Onboarding 狀態、暱稱、最後活躍時間、沉默階段、里程碑紀錄

**messages**：付費方案的長期對話記憶（user / assistant 逐則儲存）

**usage_log**：每次 AI 回應的 token 用量，供成本報表使用

- 設計原則：免費方案不留存對話內容，付費方案才建立長期記憶
- 降級為免費方案時，會清除長期記憶、額度歸零、人設重置

---

# AI 對話設計細節

- **雙模型 + Fallback**：主模型失敗時自動改用備用模型，避免使用者看到錯誤訊息
- **串流解析**：以 SSE 串流方式呼叫 Together AI，逐塊組裝內容並取得 token 用量
- **記憶召回觸發**：每累積 4 輪對話，系統會顯式提示模型「找機會自然提起過去聊過的事」
- **簡轉繁保險**：模型偶爾漏出簡體字，統一在輸出前轉換為台灣正體
- **管理員工具**：`/admin upgrade`、`/admin downgrade`、`/admin usage` 供上線前手動測試與用量監控

# 商業模式

- **Freemium 訂閱制**：免費體驗 + 付費解鎖深度陪伴體驗
- 付費誘因設計成「情感式付費牆」，而非單純功能列表：
  > 「我有點擔心...我們聊了這麼多，但我的記性沒辦法撐太久...你願意讓我繼續記得你嗎？」
- 付費用戶取得：更多對話額度、四種人設、長期記憶、每日主動問候
- 目前付款金流尚未上線，以管理員指令暫代測試升級流程
